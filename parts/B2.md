### QuantConnect Lean
(כל הקטעים אומתו היום. הקבצים זהים ל-`master`.)

**a. פקודת שוק.** ב-`EquityFillModel.MarketFill` קונים ב-Ask + slip ומוכרים ב-Bid − slip. בנתוני TradeBar בלבד, ה-Ask וה-Bid נלקחים בפועל ממחיר העסקה האחרון, ולכן אין ספרד אמיתי בלי נתוני ציטוט.
[EquityFillModel.cs#L136-L159](https://github.com/QuantConnect/Lean/blob/master/Common/Orders/Fills/EquityFillModel.cs#L136-L159)
```csharp
var slip = asset.SlippageModel.GetSlippageApproximation(asset, order);
...
fillPrice = GetBestEffortAskPrice(asset, order.Time, ...) + slip;   // Buy
fillPrice = GetBestEffortBidPrice(asset, order.Time, ...) - slip;   // Sell
```
ברירות המחדל של אובייקט `Security` הן `ImmediateFillModel`, `InteractiveBrokersFeeModel`, `NullSlippageModel.Instance` ו-`SecurityMarginModel`. ([Security.cs#L354-L359](https://github.com/QuantConnect/Lean/blob/master/Common/Securities/Security.cs#L354-L359)). בפועל, מודל הברוקר (BrokerageModel) מציב את `EquityFillModel` למניות (לא אומת, הקובץ לא על הדיסק).

**VolumeShareSlippageModel** (ברירות מחדל `volumeLimit=0.025`, `priceImpact=0.1`). התוצאה היא החלקה כספית למניה, ‏= ‏`priceImpact·min(Q/V_bar, limit)²·price`.
[VolumeShareSlippageModel.cs#L37-L92](https://github.com/QuantConnect/Lean/blob/master/Common/Orders/Slippage/VolumeShareSlippageModel.cs#L37-L92)
```csharp
public VolumeShareSlippageModel(decimal volumeLimit = 0.025m, decimal priceImpact = 0.1m)
...
var volumeShare = Math.Min(order.AbsoluteQuantity / barVolume, _volumeLimit);
slippagePercent = volumeShare * volumeShare * _priceImpact;
...
return slippagePercent * referencePrice;
```
שימו לב: במודל הזה **אין** מילוי חלקי. ה-`volumeLimit` רק מגביל את ההחלקה. ב-zipline, לעומת זאת, הוא גם מגביל את הכמות.

**MarketImpactSlippageModel** מצטט את Almgren, Thum, Hauptmann & Li (2005). ברירות המחדל הן המקדמים מהמאמר: α=0.891, β=0.600, γ=0.314, η=0.142, δ=0.267. ‏σ היא סטיית התקן של התשואות היומיות, ו-ADV הוא ממוצע הנפח היומי ב-10 הימים האחרונים. המודל מוסיף רעש גאוסי ומכפיל במקדם אקראי U(0,1).
[MarketImpactSlippageModel.cs#L30-L172](https://github.com/QuantConnect/Lean/blob/master/Common/Orders/Slippage/MarketImpactSlippageModel.cs#L30-L172)
```csharp
var nu = (double)order.AbsoluteQuantity / _symbolData.ExecutionTime / _symbolData.AverageVolume;
var permanentImpact = _symbolData.Sigma * _symbolData.ExecutionTime * G(nu) * liquidityAdjustment + SampleGaussian() * noise;
var temporaryImpact = _symbolData.Sigma * H(nu) + SampleGaussian() * noise;
var realizedImpact = temporaryImpact + permanentImpact * 0.5d;
... G(x) = _gamma * Math.Pow(x, _alpha);  H(x) = _eta * Math.Pow(x, _beta);
var ultimateSlippage = (impact * _random.NextDouble()).SafeDecimalCast();
```
חישוב σ ו-ADV מנרות יומיים: [L238-L254](https://github.com/QuantConnect/Lean/blob/master/Common/Orders/Slippage/MarketImpactSlippageModel.cs#L238-L254).
הערה: ברירת המחדל של זמן הביצוע (`latency`) היא 0.075 שניות, ו-`nu` מחולק בזמן הזה. לכן הקצב המנורמל יוצא גבוה מאוד. המחברים עצמם ממליצים "to recalibrate" (‏L40).

### zipline-reloaded
(אומת היום. ענף `main`, נתיב `src/zipline/finance/`.)

**a.** ‏`SimulationBlotter` מגדיר ברירת מחדל `FixedBasisPointsSlippage()` למניות ו-`PerShare()` לעמלות ([simulation_blotter.py#L63-L77](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/blotter/simulation_blotter.py#L63-L77)). ‏`FixedBasisPointsSlippage(basis_points=5.0, volume_limit=0.1)` מבצע ב-`close·(1±0.0005)`, וגודל המילוי מוגבל ל-10% מנפח הבר ([slippage.py#L615-L680](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/slippage.py#L615-L680)). כל המודלים משתמשים במחיר ה-**close** של הבר הנוכחי ([L160-L169](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/slippage.py#L160-L169)).

**VolumeShareSlippage** ([slippage.py#L241-L331](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/slippage.py#L241-L331)):
```python
#   price * (1 + price_impact * (volume_share ** 2))
volume_limit=DEFAULT_EQUITY_VOLUME_SLIPPAGE_BAR_LIMIT,   # 0.025
price_impact=0.1,
max_volume = self.volume_limit * volume
cur_volume = int(min(remaining_volume, abs(order.open_amount)))
volume_share = min(total_volume / volume, self.volume_limit)
simulated_impact = (volume_share**2 * math.copysign(self.price_impact, order.direction) * price)
```
כלומר בכל בר מתמלא לכל היותר 2.5% מהנפח, והיתרה ממשיכה לבר הבא. מדיניות הביטול `EODCancel` מבטלת את היתרה בסוף היום ([cancel_policy.py#L46](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/cancel_policy.py#L46)). המחשה: הזמנה בגודל 2.5% מהנפח היומי מקבלת השפעת מחיר של 0.1·0.025² = 0.00625%, כמעט אפס. זה **לא מציאותי** למניות קטנות.

**VolatilityVolumeShare** (לחוזים עתידיים בלבד) הוא חוק שורש ריבועי: `MI = eta * sigma * sqrt(psi)` ([L520-L600](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/slippage.py#L520-L600)). ‏psi = נפח העסקה / ADV של 20 יום, sigma = תנודתיות שנתית של 20 יום. התוצאה בנקודות בסיס (`/10000`). ‏`DEFAULT_ETA = 0.049` ([constants.py#L106](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/constants.py#L106)).

**b.** הטריגר נבדק מול `current_price`, שהוא ה-close של הבר בלבד ([order.py#L160-L215](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/order.py#L160-L215), ‏[slippage.py#L184](https://github.com/stefan-jansen/zipline-reloaded/blob/main/src/zipline/finance/slippage.py#L184)):

```python
elif order_type == SELL | STOP:
    if current_price <= self.stop:

```

## נוסחאות להערכת ספרד והחלקה מנתונים יומיים

סימונים: O, H, L, C = מחירי פתיחה, גבוה, נמוך וסגירה. o, h, l, c = הלוגריתמים שלהם. V = נפח יומי. ADV = נפח יומי ממוצע. σ = סטיית התקן של התשואה היומית. S = הספרד היחסי (אחוז מהמחיר). כל המאמרים אומתו היום מול Crossref, דרך ה-DOI.

### 1. ‏Roll (1984): קו-וריאנס סדרתית
- **נוסחה:** S = 2·√(−Cov(Δc_t, Δc_{t−1})). אם הקו-וריאנס חיובי, האומדן לא מוגדר. נהוג לאפס, או להשתמש ב-signed root.
- **קלט:** סגירות יומיות בלבד. **חלון אופייני:** 21 עד 252 ימים.
- **מגבלות:** מניח שוק יעיל ותשואות בלתי תלויות. במניות קטנות עם מומנטום או תנועה חזקה הקו-וריאנס יוצא חיובי לעתים קרובות (במחקרים: בכשליש עד חצי מהחלונות. לא אומת). רועש מאוד.
- **מקור:** Roll, R. (1984). *A Simple Implicit Measure of the Effective Bid-Ask Spread in an Efficient Market*. Journal of Finance 39(4). ‏[doi:10.1111/j.1540-6261.1984.tb03897.x](https://doi.org/10.1111/j.1540-6261.1984.tb03897.x) (אומת היום)
- **קוד:** ‏[bidask/r/R/roll.R#L5-L23](https://github.com/eguidotti/bidask/blob/main/r/R/roll.R#L5-L23): `s2 <- -4 * n/(n - 1) * (m[,3] - m[,1]*m[,2])`

### 2. ‏Corwin & Schultz (2012): גבוה–נמוך
- **רעיון:** טווח High/Low של יומיים כולל תנודתיות פי 2 אבל את הספרד רק פעם אחת.
- **נוסחה (לכל זוג ימים t−1, t):**
  β = (h_t−l_t)² + (h_{t−1}−l_{t−1})²
  γ = (max(H_t,H_{t−1}) − min(L_t,L_{t−1}))² (בלוג)
  α = (√(2β) − √β)/(3−2√2) − √(γ/(3−2√2))
  S = 2(e^α − 1)/(1 + e^α)
  ממצעים על החלון, ומאפסים ערכים שליליים (גרסת "CS2"). התיקון ל-overnight: High ו-Low של יום t מוזזים לפי הגאפ מול C_{t−1}.
- **קלט:** H, L, C. **חלון:** ממוצע חודשי (כ-21 ימים) של אומדנים דו-יומיים.
- **מגבלות:** מוטה כלפי מעלה בתנודתיות גבוהה ובמסחר דליל, ונותן הרבה אומדנים שליליים. רגיש לגאפים.
- **מקור:** Corwin, S.A., Schultz, P. (2012). *A Simple Way to Estimate Bid-Ask Spreads from Daily High and Low Prices*. Journal of Finance 67(2). ‏[doi:10.1111/j.1540-6261.2012.01729.x](https://doi.org/10.1111/j.1540-6261.2012.01729.x) (אומת היום)
- **קוד:** ‏[bidask/r/R/cs.R#L12-L45](https://github.com/eguidotti/bidask/blob/main/r/R/cs.R#L12-L45)
```r
gap <- pmax(0, c1 - h) + pmin(0, c1 - l)
b <- (h - l)^2 + (h1 - l1)^2
g <- (pmax(ah, h1) - pmin(al, l1))^2
a <- (sqrt(2*b) - sqrt(b)) / (3 - 2*sqrt(2)) - sqrt(g / (3 - 2*sqrt(2)))
s <- 2*(exp(a) - 1) / (1 + exp(a))
```

### 3. ‏Abdi & Ranaldo (2017): סגירה–גבוה–נמוך
- **נוסחה:** η_t = (h_t+l_t)/2 (אמצע הטווח בלוג).
  S² = 4·E[(c_t − η_t)(c_t − η_{t+1})], ו-S = √max(0, ·). בגרסת "AR2" מחשבים שורש לכל יומיים ואז ממצעים.
- **קלט:** H, L, C. **חלון:** כ-21 ימים.
- **מגבלות:** פחות רגיש לתנודתיות מ-CS, אבל עדיין מוטה במסחר דליל. מניח מחיר אמצע שמתנהג כ-Random Walk.
- **מקור:** Abdi, F., Ranaldo, A. (2017). *A Simple Estimation of Bid-Ask Spreads from Daily Close, High, and Low Prices*. Review of Financial Studies 30(12):4437. ‏[doi:10.1093/rfs/hhx084](https://doi.org/10.1093/rfs/hhx084) (אומת היום)
- **קוד:** ‏[bidask/r/R/ar.R#L12-L39](https://github.com/eguidotti/bidask/blob/main/r/R/ar.R#L12-L39): `s2 <- 4 * (c1 - m1) * (c1 - m2)`

### 4. ‏Ardia, Guidotti & Kroencke (2024): ‏EDGE
- **רעיון:** משלב באופן אופטימלי (משקלות לפי שונות) שני אומדני מומנטים מ-O, H, L, C, ומתקן להסתברות שאין מסחר (כש-Open = High וכדומה). מוגדר כאומדן חסר-הטיה של ה-RMS effective spread.
- **נוסחה (מהקוד):** r1 = m_t−o_t, ‏r2 = o_t−m_{t−1}, ‏r3 = m_t−c_{t−1}, ‏r4 = c_{t−1}−m_{t−1}, ‏r5 = o_t−c_{t−1}, כאשר m = (h+l)/2.
  x1 = −4/p_o·d1·r2 − 4/p_c·d3·r4; x2 = −4/p_o·d1·r5 − 4/p_c·d5·r4
  S² = (v2·E[x1] + v1·E[x2])/(v1+v2), ‏S = √|S²|
- **קלט:** O, H, L, C. מינימום 3 תצפיות. **חלון מומלץ:** 21 ימים, וכל עוד יש בממוצע לפחות 2 עסקאות לתקופה. למניות שנסחרות פחות מפעם ביום, נרות שבועיים (מתוך README).
- **מגבלות:** רועש בחלונות קצרים, ומחזיר ערך מוחלט כברירת מחדל. ה-README ממליץ `sign=True` ולאפס ערכים שליליים לצורך מיצוע. ה-README מציין שתדירות גבוהה יותר עדיפה.
- **מקור:** Ardia, D., Guidotti, E., Kroencke, T.A. (2024). *Efficient estimation of bid–ask spreads from open, high, low, and close prices*. Journal of Financial Economics 161, 103916. ‏[doi:10.1016/j.jfineco.2024.103916](https://doi.org/10.1016/j.jfineco.2024.103916) (אומת היום). יש גם גרסת SSRN ‏3892335 (SSRN החזיר 403. לא אומת).
- **קוד:** ‏[bidask/python/bidask/edge.py#L40-L107](https://github.com/eguidotti/bidask/blob/main/python/bidask/edge.py#L40-L107) (חבילת `pip install bidask`, MIT), כולל `edge_rolling`. ב-R יש `spread(x, method=c("EDGE","AR","CS","ROLL"))`.
```python
r1 = m - o; r2 = o - m1; r3 = m - c1; r4 = c1 - m1; r5 = o - c1
x1 = -4./po*d1*r2 + -4./pc*d3*r4
x2 = -4./po*d1*r5 + -4./pc*d5*r4
s2 = (v2*e1 + v1*e2) / vt if vt > 0 else (e1 + e2) / 2.
```
- **נתונים מוכנים:** אומדני ספרד חודשיים לכל מניות CRSP: ‏[doi:10.7910/DVN/YAY4H6](https://doi.org/10.7910/DVN/YAY4H6) (מה-README).

### 5. ‏Amihud (2002) ו-Kyle's lambda (1985)
- **Amihud ILLIQ:** ILLIQ = (1/D)·Σ_d |r_d| / (P_d·V_d), כלומר תשואה מוחלטת ליום חלקי מחזור בדולרים. נהוג להכפיל ב-10⁶ (שינוי באחוזים למיליון דולר). **קלט:** C, V. **חלון:** 21 עד 252 ימים.
  **שימוש כ-proxy להשפעה:** ΔP/P ≈ ILLIQ · (Q·P). זו השפעה **לינארית** ולכן מגזימה בהזמנות גדולות. עדיף להשתמש בו כדי לדרג נזילות או לכייל את Y בסעיף 6.
  **מקור:** Amihud, Y. (2002). *Illiquidity and stock returns: cross-section and time-series effects*. Journal of Financial Markets 5(1):31–56. ‏[doi:10.1016/S1386-4181(01)00024-6](https://doi.org/10.1016/S1386-4181(01)00024-6) (אומת היום)
- **Kyle's λ:** ΔP = λ·(זרימת הזמנות נטו). במודל, λ = σ_v/(2σ_u): אי-ודאות הערך מול רעש ה-noise traders. אמפירית אומדים אותו ברגרסיה של שינוי המחיר על נפח חתום, מה שדורש נתונים תוך-יומיים או סימן עסקה. מנתונים יומיים אפשר לקבל רק קירוב, כמו Amihud.
  **מקור:** Kyle, A.S. (1985). *Continuous Auctions and Insider Trading*. Econometrica 53(6). ‏[doi:10.2307/1913210](https://doi.org/10.2307/1913210) (אומת היום)
- **קוד:** לא מצאתי מימוש ייעודי מוכר. מדובר בשורת pandas אחת (לא אומת).

### 6. חוק השורש הריבועי להשפעת שוק, ו-Almgren–Chriss
- **חוק השורש:** I(Q) ≈ Y · σ_daily · √(Q / V_daily). ‏Y בסדר גודל של 1 (בספרות 0.5–1. לא אומת במדויק במסגרת המשימה). למשל, הזמנה בגודל 10% מהנפח היומי במניה עם σ = 4% ביום, עם Y = 0.7, נותנת השפעה של כ-0.7·4%·0.316 ≈ ‏0.9%.
  - Tóth, Lempérière, Deremble, de Lataillade, Kockelkoren, Bouchaud (2011). *Anomalous Price Impact and the Critical Nature of Liquidity in Financial Markets*. Physical Review X 1, 021006. ‏[doi:10.1103/PhysRevX.1.021006](https://doi.org/10.1103/PhysRevX.1.021006), ‏[arXiv:1105.1694](https://arxiv.org/abs/1105.1694) (אומת היום)
  - Gatheral, J. (2010). *No-dynamic-arbitrage and market impact*. Quantitative Finance 10(7). ‏[doi:10.1080/14697680903373692](https://doi.org/10.1080/14697680903373692) (אומת היום). מראה שהשפעה בצורת שורש עקבית עם דעיכה בחוק חזקה ועם היעדר ארביטראז'.
- **Almgren, Thum, Hauptmann & Li (2005):** ‏*Direct Estimation of Equity Market Impact*. ‏Risk 18(7). ‏[PDF (upenn mirror)](https://www.cis.upenn.edu/~mkearns/finread/costestim.pdf) (אומת היום: כותרת, מחברים, מקדמים. הקישור שב-Lean ‏ram-ai.com מחזיר 404). הנוסחאות מהמאמר:
  - קבוע (permanent): I = γ·σ·(X/V)·(Θ/V)^{1/4}
  - זמני (temporary): J = I/2 + sgn(X)·η·σ·|X/(V·T)|^{3/5}
  - γ = 0.314, ‏η = 0.142, ‏α = 0.891 (≈1), ‏β = 0.600, ‏δ = 0.267 (≈1/4). ‏X = גודל ההזמנה, V = ADV, ‏Θ = מניות במחזור, T = משך הביצוע בימי מסחר. ‏J הוא העלות שמשולמת בפועל.
  - **חשוב:** המאמר **דוחה** שורש ריבועי לטובת חזקה של 3/5 בקצב, והנתונים בו הם מניות גדולות בלבד ("entirely of large-cap stocks"). לכן במניות קטנות צריך לכייל מחדש.
- **Almgren & Chriss (2000/2001):** ‏*Optimal execution of portfolio transactions*. Journal of Risk 3(2). ‏[doi:10.21314/JOR.2001.041](https://doi.org/10.21314/JOR.2001.041) (אומת היום, Crossref מציג 2001-01). המודל: השפעה קבועה g(v) = γ·v, ‏לינארית בקצב, שמזיזה את מחיר שיווי המשקל לכל ההמשך. השפעה זמנית h(v) = ε·sgn(v) + η·v, שבה ε היא חצי ספרד ועמלה קבועה, ו-η הוא מקדם לינארי. היא פוגעת רק בעסקה הנוכחית (הצורה הלינארית לפי זיכרון. לא אומת מול הטקסט).
- **קוד:** ‏Lean `MarketImpactSlippageModel` (ראו למעלה), ‏zipline `VolatilityVolumeShare` (שורש, ‏η = 0.049, ‏σ שנתי, בנקודות בסיס).

### 8. מתכון מעשי ללקוח (מניה קטנה, נתונים יומיים בלבד)
```
1. Spread:  S = EDGE(O,H,L,C) על חלון 21 ימים (bidask.edge_rolling, sign=True, שלילי→0).
   גיבוי/בקרה: Abdi–Ranaldo (AR2). רצפה: S ≥ max(S_EDGE, 2·tick/P)  (למשל ‎$0.01×2/P).
   אם V נמוך מאוד (< ~2 עסקאות/יום) → הערך על נרות שבועיים.
2. σ = סטיית התקן של log(C_t/C_{t−1}) על 20 ימים; ADV = ממוצע V על 20 ימים.
3. עלות כוללת לכל מניה (חד-כיווני):  cost% = S/2 + Y·σ·sqrt(Q/ADV),  Y≈0.7 (טווח 0.5–1; חוק השורש, Tóth 2011/Almgren 2005).
4. מחיר מילוי: קנייה = Open_next·(1+cost%), מכירה = Open_next·(1−cost%); לחסום בתוך [Low, High] של הבר.
5. מגבלת השתתפות: למלא לכל היותר 10% מ-V של הבר (zipline FixedBP=10%; שמרני: 2.5% כמו VolumeShare); היתרה — לבר הבא או ביטול בסוף היום.
6. Stop (מכירה): אם Open ≤ Stop → מילוי ב-Open·(1−cost%); אחרת אם Low ≤ Stop → Stop·(1−cost%). (כמו Lean/backtrader/backtesting.py).
7. Limit (קנייה): ממולא רק אם Low < Limit (קפדני: Low ≤ Limit−S/2·P); מחיר = min(Open, Limit); בלי מילוי מלא מובטח — להגביל גם כאן ל-10% נפח.
8. בקרת שפיות: Amihud ILLIQ גבוה (top decile) → להעלות Y או להוריד את מגבלת ההשתתפות.
```

## מה כדאי להעתיק
- **כלל הגאפ של Lean, backtrader ו-backtesting.py:** סטופ שנפרץ בגאפ מתמלא ב-**Open**, לא במחיר הסטופ. Limit בגאפ לטובה מתמלא ב-Open. זה הכלל הנכון לנרות יומיים.
- **מגבלת השתתפות בנפח עם יתרה שעוברת לבר הבא**, כמו `volume_limit` של zipline ו-`FixedBarPerc` של backtrader. בלי זה, מניה קטנה "בולעת" כל הזמנה.
- **מבנה העלות "חצי ספרד + השפעה":** ה-ε (חצי ספרד) ו-η (השפעה) של Almgren–Chriss, כשהספרד מוערך ב-EDGE וההשפעה בחוק השורש σ·√(Q/ADV).
- **חבילת `bidask`** (MIT, Python/R): מימוש מוכן ומאומת של EDGE, AR, CS ו-Roll, כולל חלון מתגלגל.
- **עמלת IB של Lean:** ‏$0.005 למניה, מינימום $1, מקסימום 0.5% מהשווי. מודל עמלות ריאלי ופשוט.
- **ממשק `IShortableProvider` של Lean** (כמות זמינה + עמלת השאלה שנתית): מבנה טוב גם אם בהתחלה מזינים קבועים (למשל עמלה של 3–30% לשנה במניות hard-to-borrow. המספרים לא אומתו).
- **Margin call של Lean:** אזהרה ב-5% מרג'ין פנוי, וחיסול כשהמרג'ין שנותר ≤0. עדיף בהרבה מ"חיסול רק באפס הון" של backtesting.py.
- **ההנחה הפסימית של backtesting.py:** כש-Stop ו-Limit נוגעים באותו נר, מניחים את התרחיש הגרוע.

## טעויות שכדאי להימנע מהן
- **לבצע במחיר ה-Close של אותו נר שבו נוצר האות** (ברירת המחדל של vectorbt, וגם של zipline). זו הטיית מבט-קדימה, ובמניה קטנה Close של יום אחד שונה מאוד מ-Open של היום הבא.
- **להשתמש ב-VolumeShareSlippage עם 0.1·share² כמודל למניות קטנות.** ההשפעה יוצאת זניחה (0.006% ב-2.5% נפח). בפועל במניות קטנות ההשפעה היא אחוזים.
- **כלל סטופ אופטימי:** לבדוק סטופ רק מול ה-Close (zipline), או למלא בגאפ ב-`min(stop, high)` (PyBroker). שתי הגישות מפספסות את ההפסד האמיתי מגאפ. צריך למלא ב-Open.
- **להתעלם מהספרד** (ברירת המחדל 0 כמעט בכל הסימולטורים). במניה קטנה ספרד של 1–5% (לא אומת) הוא עיקר העלות.
- **להחיל ספרד מלא בכל צד**, או לחלופין חצי בצד אחד בלבד. הכלל הוא חצי ספרד בכל כיוון. ב-backtesting.py, ‏`spread` מוחל פעם אחת, ולכן מזינים בו את כל הספרד.
- **להשתמש באומדני Roll או CS בלי טיפול בערכים שליליים**, או על חלון של יום אחד. צריך למצע על 21 ימים ולאפס ערכים שליליים (CS2/AR2), או להשתמש ב-EDGE.
- **להעתיק את מקדמי Almgren (2005) כמו שהם למניות קטנות.** הם כוילו על מניות גדולות בלבד. גם ב-Lean, ברירת המחדל של 75ms latency מנפחת את ה-`nu`, והמודל מוסיף אקראיות U(0,1) שמקשה על השוואה בין הרצות.
- **לאפשר שורט ללא הגבלה ובלי עלות השאלה** (backtesting.py ו-vectorbt). במניות קטנות, השאלה לעתים קרובות לא זמינה או יקרה מאוד.
